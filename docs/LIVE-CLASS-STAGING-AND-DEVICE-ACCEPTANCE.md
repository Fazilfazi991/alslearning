## Long-file limits and targeted checks

- Existing browser validation reconstructs the IndexedDB Blob and calls `blob.arrayBuffer()` before WebCrypto SHA-256. That demands at least a whole-file transient buffer, and may involve copies; moving that buffer to a Worker alone would not bound memory. The prior 337 MB run's five-minute process samples could not resolve this short peak. A **targeted local Chrome probe of the saved exact 337,011,409-byte WebM** (no recapture, no external upload) read the whole file in 1,268 ms and completed WebCrypto SHA-256 in 2,074 ms total, producing `0fb09136f91b8861c104bb5ff927d29ee678344d7f8f0653d403406ee62f3229`. Aggregate Chrome-family private memory rose from 3,370.3 to 4,101.6 MiB (**+731.3 MiB sampled**, across all Chrome processes/tabs), not a per-tab peak. `performance.memory.usedJSHeapSize` after the operation was about 339.5 MB; it does not account for every native/browser allocation. The page's 50 ms timer recorded 17 ticks, longest observed gap 58.2 ms, so it remained responsive in this one desktop run. This synthetic probe exercised the equivalent full-arrayBuffer hash operation, **not** the application's IndexedDB chunk reassembly and media seek path.
- The probe origin `127.0.0.1:3040` reported a browser-estimated 10 GiB quota, 0 usage, and `persisted=false`. It is a **different origin** from the Teacher's `127.0.0.1:3000` IndexedDB store, so this is not Teacher recovery headroom. Reliable per-origin storage/quota during the actual long capture remains **NOT MEASURED**.
- Persisted chunks and recovery metadata are retained until remote review/publication. The UI reports a `QuotaExceededError` and offers a recovery download; confirm this failure mode and actual remaining bytes in a controlled test before calling it robust. The browser may evict best-effort storage; this is not a guaranteed durable backup.
- Server R2 digest is streamed. Sequential duplicate Teacher validation now returns already-validated evidence without rehashing the object; concurrent validation and Admin repeated review are not yet proven single-flight. Hosted duration/timeout and retry behavior still require measurement. Do not remove either integrity check or cap recording size silently.
- Supported **observed** Teacher environment: Windows 11 desktop Chrome 153, 15.7 GiB RAM. The 337 MB local object decoded, sought, hashed, and was retained for recovery. An aggregate browser-family hash peak is measured as above, but actual application-tab peak and its IndexedDB quota headroom remain NOT MEASURED. Other desktop/browser environments and Safari playback are not yet accepted.
