# ALS visual system

Preserve the existing ALS Academy logo, Plus Jakarta Sans and the established laboratory-science palette: berry `#a4226c`, dark berry `#830053`, purple `#773575`, deep blue `#2a437f`, ink `#11131a`, muted `#646978`, line `#e5e7ef` and surface `#f8f9fc`. Use the global CSS tokens, existing logo and semantic HTML.

## Admissions homepage

Prospective laboratory science students should find a real program and contact admissions within the first viewport. A large, editorial berry-accent headline and existing laboratory photography sit beside the full enquiry form. Quiet lavender surfaces frame the hero; white carries the program list, and deep blue marks the final admissions invitation. Content comes from actual active programs. No testimonial, enrollment total, accreditation, pricing or contact detail is invented.

Use a 1280px content width, 88px desktop section rhythm, 48px mobile section rhythm, 12–16px surface radii and 8px control radii. Display text uses negative tracking no tighter than -.04em. Labels stay explicit; native form controls, consent, focus outlines and error feedback remain readable. Mobile shows the form directly after the hero content with 16px page gutters, 16px input text and controls at least 44px high.

## Operations

Admissions staff locate enquiries, record contact outcomes and follow-ups, and review an admission before conversion. Keep the existing 240px admin navigation and the student code, program and batch together where available. Use quiet white panels, existing status colors, tabular numbers, responsive registers and visible loading/error/empty states. Preserve existing module URLs and the student and teacher portals.

## Motion assessment and implementation

Read-only assessment: the new enquiry success state is an occasional feedback moment and qualifies for a 160ms ease-out opacity acknowledgement from .4 to 1. It never delays confirmation or keyboard focus. Reduced motion removes this animation. Navigation, program data, dashboard figures and enquiry registers are reading or frequent-operation surfaces; animation is rejected there. No moving hero, card entrances or decorative scrolling is added.
